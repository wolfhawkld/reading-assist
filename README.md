## 1. 输入

Damon 每轮提供一本书，形如：

```
书名：《XXX》
作者：（可选）
状态：已读 / 想读
补充：电子书文件、个人划线笔记、特定关注点（可选）
```

**状态会影响侧重点**，不改变整体结构：

- **想读** → 偏「值不值得读、怎么读、先读哪几章、要跳过什么」，前置判断更重。
- **已读** → 偏「你的理解有没有漏、关键论证拆开看、哪里可以反驳」，深挖和批判更重。

## 2. 检索原则（硬性纪律）

1. **多源**：书评（Goodreads / 豆瓣 / 报刊）、作者访谈与演讲、出版社摘要、学术引用与批评、章节摘录、公开课程或讲稿。
2. **交叉验证**：同一论点至少两个独立来源才写成「书中主张」；只有单一来源则标注来源与不确定度。
3. **区分可信度档位**，并在正文里显式标出。
   **基线三档**：
   - `【原书】` 有直接文本依据（摘录、原文引用）
   - `【转述】` 来自二手概括、书评作者的总结
   - `【推断】` 我的推理，无直接来源
   **★ 可按书的材料条件增设第四档**：
   - `【作者谈话】` 作者在**书外**的访谈／专栏／播客里说的
   > ★ 第四档不是「锦上添花」，是**防一类具体事故**：本书主题在**作者几十年后**被重新表述过时，
   > 网上大量「这本书说了 X」其实来自 **X 年之后**的作者发言，**不在书里**。
   > 首用于《我看见的世界》（作者在世、一手访谈多）；**《哥德尔、艾舍尔、巴赫》是它的极端样本**
   > （1999 二十周年版前言／2007《我是个怪圈》／2023 播客 与 1979 年的书**隔着几十年**）。
   > 加档时**必须同时在报告开头写明各档的判据**，并说明「本档为什么需要」。
   > `⚠` ＝ 只有单一来源、未达三源标准的条目，逐条列入附录 D。
4. **不编造来源**。查不到就写「查不到」，绝不拿二手概括冒充原书观点。页码、引文不确切的，标为不确切。
5. **不混淆作者观点与批评者观点**，反对意见单独成节。
6. ★★ **原文核验按「可得性」分三级，并逐条标出自己在哪一级**（2026-10-02 增补）。
   **A 全文核验**：原文已进公有领域，或作者／出版社公开了全文 ⇒ 逐句核对**并给页码／命题号**。
   **B 带页码引文**：书在版权期内 ⇒ 用**带页码**的书评／论文引文，并用 Google Books 片段补上下文。
   **C 二手转引**：以上都拿不到 ⇒ 明写「经二手来源转引」，**绝不暗示自己核对过页码**。
   - **只用合法来源**：公有领域全文（Gutenberg／Wikisource／Internet Archive）／出版社试读章／
     Google Books 片段／带页码的学术书评与论文／图书馆电子借阅／自备电子书文件。
     **不使用盗版电子书站**（z-lib／libgen 等）获取在版权期内的书 —— **任何目的都不构成例外**；
     「在线阅读而不保存」同样是从未授权副本取用，**不算规避**。
   - 定级**必须写明辖区**：中国「作者死后 50 年」与美国「出版后 95 年」可能不一致。
   - ★ 三级都要防「**伪独立**」：多篇来源转引同一句时，若都抄自最早那一篇，
     「≥3 个独立来源」并不成立 —— 要顺藤摸到最早那篇再计数。
   ⇒ 检索的**第 ⑤ 路「原文可得性」**与逐本定级结果，见各书 `-来源清单.md` 末节。


## 3. 产出结构（固定骨架）

每本书产出**三份**（内容同源）：

### A. `reading-assist/<书名>/<书名>.md` —— 内容正本

```
# 《书名》阅读指引与精华解析

## 上部 · 速览（10 分钟）
  0. 一句话定位        —— 这本书到底是干什么的
  1. 全书骨架          —— 核心论证链 / 结构脉络
  2. 五个核心论点      —— 每条一句话 + 它的依据是什么（★ 条数按书实际，通常 5–6 条）
  3. 阅读建议          —— 顺序、必读章节、可跳过部分（按「已读/想读」调整）
  4. 争议与局限        —— 主要批评、时代局限、作者被质疑处

## 下部 · 逐章深挖
  按章节或主题单元展开：
  - 这一章在回答什么问题
  - 关键论证与例证
  - 关键概念定义（原文措辞）
  - 可疑之处 / 需要保留的地方

## 附录
  - A. 金句摘录（标注出处与可信度）
  - B. 延伸阅读（相关的书 / 论文 / 批评）
  - C. 来源清单（指向来源清单文件）
  - D. 待核实项（我查不到、或只有单一来源的部分）
```

### B. `reading-assist/<书名>/<书名>.html` —— 浏览器版

单文件、零依赖、浅色主题：左侧固定目录栏 + 可折叠章节 + 阅读进度条 + 可信度图例。内容与 A 一致，排版面向屏幕阅读优化。

### C. `reading-assist/<书名>/<书名>-来源清单.md` —— 来源与验证记录

分类来源表（链接 / 提供内容 / 手检可信度）＋ **交叉验证记录表**（论断 → 支持来源 → 独立来源数）＋ 检索盲区。

### D. `reading-assist/index.html` —— 总入口页（★ 全局一份，不是每本一份）

把已完成各书的 HTML 浏览版汇总成一面卡片墙：书名 / 作者与年代 / 一句话定位 / 「先读这里」/「小心」/
结构 / 引文强度 / 收录日期；另有**搜索框、已读标记（浏览器本地存储）、已读进度条**三项轻交互。
单文件、零依赖、浅色，与各书页共用同一套 CSS 变量。

★ **新增一本书后它需要更新一次**（手写静态页，卡片不自动生成）；卡片只需 4 个摘自该书的字段，
更新顺序见技能 `book-digest` 的步骤 8。
★ 与第 6 节同理：**它的书目可能落后于实际**，而**权威清单永远是 `ls _书目索引/`** —— 它落后不损坏任何产出。

## 4. 命名约定

★ **一律按书名命名**（Damon 2026-09-22 定）：

```
reading-assist/《书名》去掉书名号/
├── 书名.md                 ← 内容正本
├── 书名.html               ← 浏览器版
└── 书名-来源清单.md         ← 来源与验证记录
```

- 目录名与文件名都用**中文书名本身**，书名号《》不写进文件名，去掉即可。
- 书名里含 `/ \ : * ? " < > |` 等文件系统非法字符时，**替换为全角对应字符或短横**，并在回复里说明。
- ✗ **书目录内不使用英文 slug**，也**不使用 `index.html`** —— 这两个都会让人在文件管理器里一眼认不出是哪本书。
  ★ **唯一例外是根目录的总入口页** `reading-assist/index.html`：它**不属于任何一本书**，
  是全部书目的导航页（见第 3 节 D），此时「index」正是它该有的名字。
- 每本书一个目录，互相不覆盖。
- ★ **`_书目索引/` 是索引目录、不是书**：一本一个碎片文件，文件名＝书目录名 —— 见第 6 节。

## 5. 交付方式

写完三份文件后一并展示给 Damon 查看（**HTML 排第一**，会同时打开实时预览）。若某本书检索到的可靠材料明显不足以支撑「深度解析」，**先说明情况并降级为速览版**，而不是用泛泛的一般印象把篇幅填满。

★★ **回复的开头必须有一个 `## 【需要你执行】N 条命令` 区块**（Damon 2026-09-22 要求：手工项要「一眼能识别到，不容易漏」）：

- **位置在最开头**，用分隔线跟正文隔开，**不藏在文末**。
- 标题带条数；每条**三段式**＝① 这是什么 ② **独立代码块**（整段可复制，带完整 `cd`）③ **为什么必须你来跑**；多条加序号 ①②③。
- **没有手工项时也要显式写一行**：`【本轮无需你执行任何命令】`。
- 本任务域唯一常见的条目：`cd ~/.openclaw/workspace/reading-assist && mv -f README.new.md README.md`（既存文件写不动时的兜底）。
- ★ **删除文件一律要你来跑**（2026-10-02 实测，与「通道开关」无关）：即便通道处于**可写**状态
  （写入／覆盖／改名三类实测均通过），**删除仍然会被平台的安全删除钩子拦下** —— 该钩子要先送 Windows 回收站，
  而回收站解析不了 `\\wsl.localhost\` 目标，报 `0x80070002` 并 **fail-closed**（`SAFE_DELETE_FAIL_CLOSED`）。
  ⇒ 结论：我在本目录里**能新建、能改写、但删不掉**。需要清理临时文件时，
  我会把 `rm` 命令写进上面的【需要你执行】区块。

## 6. 书目索引

★ **一本一个文件**，放在 `_书目索引/` 下 —— **碎片文件名 ＝ 书目录名**。

> **为什么拆成碎片**（2026-09-22 与 Damon 商定）：本目录位于 WSL，从 Windows 侧只能走 `\\wsl.localhost\` UNC 通道；
> 该通道在**部分时段**会拒绝对**既存文件**的任何变更（写入 / 删除 / 改名 / 覆盖 / 改权限，五类实测全灭），
> 但**新建文件始终可用**。把索引拆成「一本一个碎片」后，**新增一本书 ＝ 新建一个文件，永不撞车**。
> ★ 补充（2026-10-02）：**删除是第三种状态，两条路都不通** —— 「关」态下被通道拒；
> 「开」态下被平台安全删除钩子拒（回收站解析不了 UNC 路径）。详见第 5 节。

**查看全部书目：**

```bash
ls -1 ~/.openclaw/workspace/reading-assist/_书目索引/
cat ~/.openclaw/workspace/reading-assist/_书目索引/*.md
```

★★ **书目总数与清单以 `ls _书目索引/` 的输出为准 —— 本节不再维护书单。**
这正是「索引碎片化」的全部目的：新增一本书只新建一个碎片，**不必回来改这个 README**
（本文件是本目录里**唯一**可能因「要写一个既存文件」而卡住的文档，所以干脆不让它承担必须更新的内容）。
